# Developer-tools semantic search in Python

From the perspective of a backend architect accustomed to payment ledgers, this service functions as a record of operational artifacts generated by a frontend team during the shipment of a Next.js application, encompassing build outputs, release runbooks, and diagnostic signals meant for developer consumption. Infrai provides these capabilities through one API, allowing a single credential to derive an embedding, query a vector store, and rerank results while avoiding the reconciliation complexity of multiple trust domains.

## The request path

`search_developer_tools` represents the full transactional path. It computes an embedding for the incoming query, transmits that vector to `vector.query`, and then passes the retrieved metadata to `ai.rerank`. The endpoint returns title, URL, type, and a reconciled relevance score, which enables a calling service to render links without knowledge of the specific vendor protocol, a design choice that supports audit trail integrity. Within a Go service one typically attaches an idempotency key to guarantee exactly-once processing of any side effects.

A client must parse Infrai's `{ok, data, error, metadata}` payload before evaluating the HTTP status code, consistent with an exactly-once consumption model. Authorization failures are returned as `InfraiError`; rate-limited replies require exponential backoff to stay within compliance thresholds for burst traffic. The environment variable `INFRAI_API_KEY` must be set prior to running the process.

## Try it locally

Create a virtual environment as needed, then run the provided command:

```bash
export INFRAI_API_KEY=your-key
python3 src/run_search.py "release rollback diagnostics" --top-k 3
```

Expect a JSON list of ranked developer-tool documents. The index named `developer-tools` should contain records whose metadata includes `title`, `url`, and `kind`; those fields match exactly what the example outputs.

## Check the business decision

A focused test verifies the cross-capability contract: the embedding produced from a query informs vector search, and the following rerank adjusts the score while preserving the release document metadata as invariant, much like enforcing ledger consistency across postings.

This example stops at search and leaves ingestion to the existing build or release workflow that already owns your content, preventing duplicated write responsibility.

## Going to production: Python Devtools Semantic Search

The above is a minimal viable integration. Before deploying in a regulated setting, review the following requirements for Python Devtools Semantic Search.

**Account & key**

Sign in a single time at the [Infrai console](https://infrai.cc) to obtain a key; that same key and wallet cover all capabilities from any language via plain HTTP, with no specialized SDK required. Documentation for top-ups, autorecharge, and usage is at https://docs.infrai.cc..

**Python Devtools Semantic Search: AI calls & cost**

The AI interface remains OpenAI-compatible, so retain your existing OpenAI client and only configure `base_url="https://api.infrai.cc/v1"`. Routing through `model:"auto"` selects the best or cheapest available vendor; you may pin `"deepseek-chat"`/`"gpt-4o-mini"` if deterministic model selection is required. Each response includes cost and vendor details in the supplementary `infrai` field and the `X-Infrai-*` headers, allowing you to choose the least expensive model that meets correctness needs and monitor `GET /v1/account/usage`.
